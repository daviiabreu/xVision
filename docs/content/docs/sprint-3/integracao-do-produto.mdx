title: Integração do produto
description: Fluxo entre frontend, API, pipeline e configuração reproduzível de execução

A aplicação permite criar uma conta, enviar um clipe de finalização, acompanhar a fila e a etapa
atual do pipeline e abrir o resultado. A tela de resultado reúne as métricas, o vídeo processado e
uma evidência visual para cada etapa disponível.

Não existe email ou senha padrão do produto. Cada pessoa cria a própria conta e senhas precisam
ter pelo menos 12 caracteres. Credenciais usadas em demonstrações locais são temporárias e não
fazem parte do código ou da imagem de produção.

## Fluxo implementado

1. O frontend reserva um identificador em `POST /v1/videos/upload-url`.
2. O arquivo é enviado como binário para o endereço temporário recebido.
3. A API registra o trabalho, informa a posição na fila e atualiza o progresso a cada etapa.
4. `GET /v1/videos` mantém o histórico da conta sincronizado entre sessões e dispositivos.
5. Quando o processamento termina, `GET /v1/videos/:id` entrega métricas, tempos, motivos de falha,
   imagens de evidência e o endereço do vídeo processado.

O frontend usa o intervalo `reconsultar_em_s` devolvido pela API. Assim, o ritmo de consulta pode
ser ajustado no serviço sem publicar uma nova versão da interface. Uma falha temporária na
consulta não encerra o acompanhamento dos vídeos que continuam em processamento.

## Acesso e recuperação de senha

O login oferece acesso direto à recuperação de senha. `POST /v1/auth/password/forgot` recebe o
email e devolve a mesma mensagem para contas existentes e desconhecidas. Quando a conta existe,
o serviço cria um token aleatório, persiste apenas seu hash e envia um link com validade padrão de
30 minutos. `POST /v1/auth/password/reset` consome o token uma única vez e atualiza a senha. Trocar
o email ou a senha invalida todos os links de recuperação ainda abertos. Trocar ou redefinir a
senha também invalida as sessões emitidas anteriormente.
Pedidos ainda aguardando o envio do email também são descartados se a credencial mudar antes da
emissão do token. A gravação verifica email, versão da sessão e revogação na mesma transação.

O envio depende de SMTP e de uma URL pública configurados pelo operador. Sem essa configuração, a
rota responde `503` e a interface explica que a recuperação ainda não está disponível naquele
ambiente. Isso evita exibir uma confirmação de email que nunca foi entregue. As variáveis estão
documentadas no `.env.example`:

```dotenv
XVISION_PUBLIC_URL=https://xvision.exemplo.com
XVISION_SMTP_HOST=smtp.exemplo.com
XVISION_SMTP_PORT=587
XVISION_SMTP_USER=
XVISION_SMTP_PASSWORD=
XVISION_SMTP_FROM=xvision@exemplo.com
XVISION_SMTP_STARTTLS=1
XVISION_PASSWORD_RESET_TTL_S=1800
```

Pedidos e confirmações também têm limite por origem. Links expirados, já usados ou inválidos
respondem da mesma forma e nunca revelam o token ou o hash persistido.

## Integração automatizada pela API

A página pública `/api-docs` pode ser aberta a partir do login, sem criar uma conta. Ela reúne o
fluxo de integração, um exemplo com `curl`, o Swagger incorporado, o contrato OpenAPI e uma coleção
Bruno pronta para download. Em produção, o Nginx encaminha `/docs`, `/openapi.json` e `/bruno.zip`
para a mesma API usada pelo frontend.

Uma integração de sistema deve usar um token de serviço, e não a senha de uma pessoa. O operador
pode emitir um token com o comando abaixo. O valor aparece uma vez e o banco guarda somente o
hash:

```bash
docker compose exec api python -m api.tokens criar integracao-footstats
```

O fluxo atual é REST com consulta periódica:

1. `POST /v1/videos/upload-url` reserva o envio.
2. `PUT` no `uploadUrl` recebido envia o vídeo como binário.
3. `GET /v1/videos/status/:id` informa fila, etapa e progresso.
4. `GET /v1/videos/:id` entrega o resultado terminal.

Ainda não há webhook de conclusão. Um sistema externo precisa consultar o status usando o
intervalo `reconsultar_em_s`. A interface informa esse limite para não apresentar como pronto um
contrato que ainda não existe.

A reserva vale 15 minutos por padrão. Se o cliente reservar e nunca iniciar o `PUT`, a API marca o
trabalho como falho na consulta seguinte e recusa um envio tardio. O prazo pode ser alterado por
`XVISION_UPLOAD_RESERVATION_TTL_S`.

## Informações apresentadas

| Momento | Informação visível |
| --- | --- |
| Envio | nome, tamanho e porcentagem transferida |
| Fila | posição do trabalho e situação pendente |
| Processamento | etapa atual, etapas concluídas e porcentagem total |
| Resultado | situação final, quantidade de métricas, duração e motivo quando houver falha |
| Auditoria | quadro anotado, duração, situação e métricas de cada etapa |

Os quadros são derivados do próprio clipe enviado e ficam limitados a 720 pixels no maior lado. O
JPEG é incluído no resultado como Data URL. Se a geração da evidência falhar, a análise continua e
o campo fica nulo. A imagem usa o mesmo índice da percepção escolhida, incluindo quando a amostra
mais próxima não coincide com o instante do chute.

Resultados anteriores à inclusão dos metadados por etapa continuam acessíveis. Na leitura, o
status booleano legado determina a situação: verdadeiro vira `ok`, falso vira `failed`. Esses
registros não distinguem falha de etapa ignorada e não contêm tempo medido. A adaptação preserva
o conteúdo salvo no banco.

## Navegação responsiva

Em telas amplas, o menu lateral pode ser recolhido para liberar espaço para o resultado. A largura,
os textos e a marca mudam de forma gradual durante 500 milissegundos; os ícones continuam visíveis
no estado compacto. A preferência fica salva no navegador e é restaurada na próxima visita.

No celular, a navegação sai do cabeçalho e abre como um painel lateral sobre a página. O painel
mantém análises, documentação da API, configurações da conta, identificação e saída no mesmo lugar.
As configurações ficam no fim do painel, junto aos controles da pessoa conectada. O painel fecha
pelo botão, por toque no fundo ou pela tecla `Esc`, bloqueia a rolagem da página enquanto está
aberto e devolve o foco ao controle do cabeçalho. Quando o sistema solicita menos movimento, as
transições são removidas.

## Configurações da conta

A opção no fim da barra lateral abre uma área protegida para acompanhar o uso e alterar os dados de
acesso. `GET /v1/auth/me/statistics` agrega todos os vídeos da conta no banco, sem depender da página
ou do filtro atual do histórico. A interface apresenta total, finalizadas, em andamento e com falha.

A troca de email em `PATCH /v1/auth/me` exige a senha atual, normaliza o endereço e preserva o
identificador da conta. Por isso, análises anteriores continuam ligadas à mesma pessoa. Um email já
usado responde com conflito e não altera a sessão. A troca de senha em
`POST /v1/auth/password/change` também exige a senha atual, rejeita a repetição da credencial e
mantém o mínimo de 12 caracteres aplicado no cadastro e na recuperação. A resposta traz uma nova
sessão, que o frontend substitui antes de continuar; as sessões antigas deixam de ser aceitas.

## Execução local reproduzível

O `compose.yaml` sobe a API, o frontend e um volume persistente. O navegador acessa somente a porta
do frontend; o Nginx encaminha os caminhos `/v1/` para a API na rede interna.

```bash
cp .env.example .env
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Copie o valor gerado para `XVISION_AUTH_SECRET` no `.env` e suba os serviços:

```bash
docker compose up --build --wait
```

A interface fica em `http://localhost:3000`. A API não publica outra porta no Compose: o Nginx
encaminha `/v1/`, `/docs`, `/openapi.json` e `/bruno.zip` pela mesma origem. Ele substitui o
`X-Forwarded-For` pelo endereço que abriu a conexão, e só nesse arranjo a API confia no cabeçalho
para aplicar limites por origem.

As sondas de saúde verificam frontend e API. Os arquivos enviados, o banco de trabalhos e os
renders permanecem no volume `xvision-var` após uma reinicialização. Na primeira subida, o serviço
`state-init` copia sem sobrescrever o conteúdo de um diretório `var/` legado para o volume e ajusta
a propriedade dos arquivos para o usuário sem privilégios da API.

Para encerrar sem apagar o volume:

```bash
docker compose down
```

### Email local com Mailpit

Para testar a recuperação de senha, acrescente `compose.mailpit.yaml` ao comando de subida:

```bash
docker compose -f compose.yaml -f compose.mailpit.yaml up --build --wait
```

Esse arquivo adiciona o Mailpit 1.31.1 e configura a API para enviar por `mailpit:1025`, sem
autenticação nem STARTTLS, com remetente `xvision@example.test`. A API aguarda o Mailpit ficar
saudável antes de iniciar. O link de recuperação aponta para `http://localhost:3000` e acompanha
`XVISION_FRONTEND_PORT` quando a porta do produto é alterada.

Crie uma conta, abra a recuperação de senha no login e informe o email cadastrado. A mensagem
aparece na [caixa local do Mailpit](http://localhost:8025); abra o link recebido para definir a
nova senha. Se a porta 8025 estiver ocupada, configure `XVISION_MAILPIT_PORT` no `.env` e abra essa
porta no navegador.

O Mailpit captura as mensagens para inspeção e não entrega emails à caixa real do destinatário.
A interface fica acessível somente no computador local e o SMTP somente na rede do Compose.
As mensagens são temporárias e desaparecem quando o contêiner é removido. A configuração segue as
[portas oficiais do Mailpit](https://mailpit.axllent.org/docs/install/docker/) e usa seu
[endpoint de prontidão](https://mailpit.axllent.org/docs/integration/healthcheck/).

Encerre o ambiente com os mesmos arquivos:

```bash
docker compose -f compose.yaml -f compose.mailpit.yaml down
```

Em ambientes que precisam entregar emails reais, use apenas `compose.yaml` e configure
`XVISION_SMTP_*` e `XVISION_PUBLIC_URL` para o servidor de email e endereço público do produto.

## Verificação

Os testes do frontend cobrem autenticação, listagem, filtros, upload com progresso, atualização
automática, resultados, erros e acessibilidade. O teste de produto com Playwright cria uma conta,
envia um vídeo real pelo navegador, aguarda o pipeline, abre uma evidência e recarrega resultado e
histórico. No CI, o teste reinicia a API sobre o mesmo volume, entra novamente, confirma o histórico
e baixa um render autenticado. O painel móvel também é testado com aprisionamento de foco,
fechamento por `Esc` e devolução do foco ao botão que o abriu.

```bash
cd src/interface
npm run lint
npm run types:check
npm test
npm run build
```

O contrato da API também é verificado pela suíte Python e pela cópia versionada do OpenAPI.

## Limite atual

O fluxo de produto está integrado, mas o conteúdo das métricas depende dos módulos e extratores
declarados em `src/config/pipeline.toml`. Uma etapa ausente não é transformada em zero ou falso: o
resultado informa indisponibilidade e registra o motivo. A execução embarcada e suas medições são
documentadas separadamente pela frente responsável pelo dispositivo.
